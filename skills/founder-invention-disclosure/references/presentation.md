# One founder report, three outputs

Deliver `disclosure.md`, `disclosure.json`, and `disclosure.html`. Start with a short executive summary, then problem/solution/intended advantages, core concepts, related-concept differentiation questions, products/innovators, founder questions, and sources/scope. Favor short paragraphs with explicit labels and a small set of concepts. Avoid a dense attorney glossary, unexplained acronyms, claim charts, taxonomy machinery, and numerical patentability ratings.

The HTML dashboard embeds its own CSS and JavaScript and performs no network requests on load. Source pages open only when deliberately clicked. Search narrows core, related, and landscape entries; the executive summary and disclosure remain visible. Show each relationship explicitly using names, not only IDs. Keep uncertainties, evidence limits, source dates, and inventor-versus-inference labels visible. Preserve complete structured data in the JSON download. Include Markdown/JSON downloads and print/save-PDF; print all findings even when search is active and restore the reader's filter afterward. All core content must remain readable without JavaScript.

Markdown should carry the same substantive findings, source links/locators, questions, and limits. It is an invention disclosure draft, not a formal legal filing. Do not imply that the HTML's design makes an inference verified. Escape all source text; accept only HTTP(S) public source URLs. Do not load fonts, analytics, source previews, or remote libraries. Install the CSS, JS, and Python script together. Never publish a report merely to make the HTML viewable.

Before delivery validate references, inspect desktop and narrow-width layouts when browser tools are available, and exercise search/reset/empty results, both downloads, source navigation, print expansion/restore, no-JavaScript readability, and absence of external requests or console errors. State testing gaps when tools are unavailable. A renderer test is not substantive patent validation.
