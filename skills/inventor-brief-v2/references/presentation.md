# Inventor Brief v2.0 — quick brief with optional depth

Default to four concise sections: “What the AI understands”, “Similar ideas & innovators”, “What would help next”, and “Initial patent-strength view”. Show one short understanding paragraph, at most three comparison cards, up to three requests, and a compact provisional status card. Target 250–350 words initially visible, excluding navigation. Do not repeat basis/confidence paragraphs or the same caveats under every visible card. Put interpretation evidence and assessment reasons behind small detail controls, with the complete disclosure, sources, and research log under one “Full disclosure, evidence & sources” control. Preserve the same information in Markdown and JSON; do not delete qualifications to shorten the view. Print expands all details and restores the prior reading state afterward.

Comparison links must open the relevant collapsed record and reveal its evidence. Keep source anchors working across collapsed sections. A no-JavaScript reader can expand details normally. Older reports use existing supplied summary/comparison content as a fallback and explicitly say when no patent assessment was authored.


Deliver `disclosure.md`, `disclosure.json`, and `disclosure.html`. Keep problem/solution/intended advantages, core concepts, differentiation questions, products/innovators, founder questions, and sources/scope in the expanded full disclosure. Favor short paragraphs with explicit labels and a small set of concepts. Avoid a dense attorney glossary, unexplained acronyms, claim charts, taxonomy machinery, and numerical patentability ratings.

The HTML dashboard embeds its own CSS and JavaScript and performs no network requests on load. Source pages open only when deliberately clicked. Search narrows core, related, and landscape entries; the executive summary and disclosure remain visible. Show each relationship explicitly using names, not only IDs. Keep uncertainties, evidence limits, source dates, and inventor-versus-inference labels visible. Preserve complete structured data in the JSON download. Include Markdown/JSON downloads and print/save-PDF; print all findings even when search is active and restore the reader's filter afterward. All core content must remain readable without JavaScript.

Markdown should carry the same substantive findings, source links/locators, questions, and limits. It is an invention disclosure draft, not a formal legal filing. Do not imply that the HTML's design makes an inference verified. Escape all source text; accept only HTTP(S) public source URLs. Do not load fonts, analytics, source previews, or remote libraries. Install the CSS, JS, and Python script together. Never publish a report merely to make the HTML viewable.

Before delivery validate references, inspect desktop and narrow-width layouts when browser tools are available, and exercise search/reset/empty results, both downloads, source navigation, print expansion/restore, no-JavaScript readability, and absence of external requests or console errors. State testing gaps when tools are unavailable. A renderer test is not substantive patent validation.
